# Protected legacy activity qualification

This explicit managed offline tool preserves frozen `user_activity` originals and produces typed protected exception dispositions. It opens no database connection and imports no operational activity. It is not a normal-host command or a Native AOT qualification.

Build with `dotnet build ops/migration/legacy_activity/Activity.csproj`. Execute the resulting `Activity.dll` only inside an authorized, resource-bounded, network-isolated copied-data environment, with `SHOP_ALLOW_PROTECTED_LEGACY_ACTIVITY=1` and one absolute output-directory argument named `teleg-activity-qualification-*`.

Mount its `inputs/` directory read-only. It contains the exact frozen `source-plan.json`, T066-qualified `original.plan` membership/archive manifest, and separate `users.000000.jsonl` / `user_activity.000000.jsonl` chunks. Each line is the original `[source key, to_jsonb(row)::text]` pair; chunks contain at most 500 rows, with no missing middle chunk. The tool recomputes the frozen keyed full-table commitments before and after preservation. Counts alone are insufficient. Source plans, membership provenance, key files and staged inputs must also be independently bound to their previously qualified originals by the host reviewer.

`inputs/keys/service-config.json` and its referenced brand-key files require owner-read-only permissions. Use the existing independently authorized single-brand JobHost keyring, without inventory access. Keep all inputs and results private on the owner server. No customer records, identifiers, key material, original details or private receipts belong in Git.

The output consists of an immutable `activity.plan`, existing-format encrypted originals in `teleg-history-archive-activity/`, an immutable typed `dispositions.private.bin` and count-only `result.redacted.json`. The private binary index contains a row count followed by record GUID, original source ID, original UTC ticks, proven membership GUID or empty GUID, finite exception code and archive digest. A fresh process must reproduce the same plan, index, ciphertext and summary. Independently decrypt and compare every original and disposition before accepting the run.

The exception codes distinguish unbound membership, unverified interaction, unverified checkout and unsupported producer. An original user reference may bind to its exact frozen membership mapping; actor identity is never treated as customer ownership. Legacy start/menu/help, shop and product logging lack verified update/outcome/replay authority. Legacy checkout logging does not establish the target's exact context and immutable event clock. Other producers have no implied target-registry meaning. Preserve all original fields and times rather than inventing those facts.

`UserActivityRecord` is an opt-in archive projection. Its `activity` target kind identifies protected evidence, not a row inserted into `legacy_id_map` or `bot_activity_events`. The existing twenty-family default selection and all earlier projection ordinals remain unchanged. The target activity registry, schema, replay fences and 180-day operational cutoff are unchanged. Protected source preservation and its retained key/backup dependencies use their separate approved policy.
