# Protected historical archive qualification
T064/T066 continue from the completed protected wallet batch. This operation preserves complete eligible historical records outside the canonical typed business database; it does not fabricate typed orders, classify unknown prepaid ownership, activate discounts, admit stock or settle money.

`LegacyArchiveFiles` uses the existing source-record proof, authenticated brand cipher and legacy re-encryption implementation. Each private file binds the exact frozen manifest, brand, projection, target, complete encrypted original record and authenticated recovered fields. Source bodies and original credentials are never written as plaintext. New files publish by exclusive atomic rename after file flush; replay reopens the existing evidence without overwriting it or changing its digest. Leftover unpublished pending files do not count as archives. Missing or changed published records reject. This qualifies process-level reload/replay; storage backup/restore and operational durability remain separate gates.

Target-only reads require the target brand keyring and frozen manifest, not the old source keys. Explicit migration verification additionally decrypts the original supported Fernet fields with current/previous source keys and compares them byte-for-byte to the recovered target fields. Field names, counts, context and digests are checked. Original key dependencies remain protected; no key deletion or production key rotation is performed.

`Platform.SchemaRunner --qualify-history-archive --job-file ABSOLUTE_PRIVATE_FILE --receipt NEW_PRIVATE_FILE.receipt.json` requires Linux and both `SHOP_ALLOW_PROTECTED_ARCHIVE_QUALIFICATION=1` and `SHOP_ALLOW_PROTECTED_SOURCE_INSPECTION=1`. A version-one, ten-field private job supplies source connection/plan, previously frozen wallet plan/state, original register, private legacy-key bundle, separate qualification-only target secret directory/manifest and private `teleg-history-archive-*` work directory. Only the three pinned archives and the existing restricted source-copy identity are accepted. The operator never connects to the destination in the wallet manifest and never applies schema or writes commerce tables.

The original keys remain on the owner server. Qualification may read only the approved source keys into owner-private server-local inputs; no key, source row, amount, identity or credential is returned in receipts or published. Newly generated qualification target keys remain separate from production configuration and are bound through the existing scope-checked secret loader. Changed source/job/key/manifest inputs reject on resume.

The source reader's optional row visitor receives rows during the single read-only repeatable-read verification transaction. Collected rows are untrusted until complete table counts/HMACs, schema and permissions all pass; the operator only collects bounded memory and writes no archive before that success. The existing twenty-family admission rules are reused: linked historical inventory only, active nonremoved catalog records only and zero-amount transactions only; other historical supported families retain full original records. Unassigned saleable inventory is not admitted. Original immutable archives and the wallet register retain the excluded data. This family archive is not a replacement for the entire original 56-table backup.

Every selected record is source-proof/coverage checked, archived, replayed, reloaded and decrypted with only the new target keys. Original supported encrypted fields additionally roundtrip with original source keys. Archived orders are projected only through the existing member/brand-bound read-only history reader; absent or rejected terms stay unknown. Complete original payment, coupon, delivery, supplier, service and refund fields remain protected evidence without new financial or operational assertions. All source commitments are checked again afterward. The frozen aggregate archive digest rejects changed record sets or ciphertext on a later run.

Managed and shared native fixtures exercise file replay/reload, new-key-only reads, original-field comparison, wrong owner/keys/source/manifest, changed ciphertext/field/shape, missing files, shared permissions and symlinks. Source-copy fixtures check complete streaming and visitor rejection; candidate tests protect the stock/ledger/catalog boundaries. Actual protected archive creation and field counts remain unexecuted until the exact new CI-built operator passes on all three copies. Native results must distinguish archive fidelity from canonical commerce/paid-obligation parity. T064/T066 stay open; T068 and release remain unexecuted and separately gated.
