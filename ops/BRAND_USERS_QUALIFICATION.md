# T018–T020 brand membership and private-DM flow

Qualification pending. Reuse the canonical T008 brands, brand_channels and users tables; no 0003 migration or telegram_sessions table is necessary. The baseline remains 28 tables with its original SQL/catalog identity.

T018 tests three memberships for the same Telegram identity, independent language/block/marketing settings and wallet ownership, every foreign-brand flow-order pairing, same-brand other-member order ownership, foreign listings and rollback. Contract tests reject forged brand selectors inside callback envelopes at the existing authenticated brand boundary. Actual Telegram source verification, sender/private-chat proof, callback parsing and operation authorization remain T022; these tests do not qualify a live Telegram router.

T019 qualifies membership uniqueness/immutable identity, positive customer destinations, separately scoped negative-ID channel metadata, absence of a telegram_sessions relation and exact single-revision flow transitions. These are additional assertions over the reviewed baseline, not new DDL.

T020 adds BrandUserStore with typed snapshots/finite flow states and explicit positional SQL. Every operation rechecks the authenticated brand, registered bot ID and active brand; actor operations additionally check the actual verified sender ID and membership. ObservePrivateAsync is an internal integration boundary for a verified private ingress, not proof of Telegram transport: T022 must authenticate source, reject bots/groups and assert the actual sender/private chat before calling it. Never pass a callback-supplied actor as the verifiedActorId argument. First contact creates one brand membership with that brand's default language, keeps existing preferences and does not create a wallet or grant backend privilege. No financial or provider work is performed.

Preference changes require reachable, non-banned membership. Flow mutation compares the current membership revision, advances exactly once, and binds optional order/product IDs through the canonical database guards. A stale/expired/unreachable/foreign target poisons the transaction; earlier writes cannot commit. Idle clears all pointers. An expired flow may be cleared or replaced by a fresh catalog start at its current revision, but cannot continue purchase/support state. Snapshots are data, never authorization. Returned state is redacted by ToString. No raw callbacks/messages are persisted. Outgoing DM lookup derives the positive destination from the current same-brand membership and rejects unknown/blocked/banned/stopped targets. It does not authorize any particular notification or credential manifest; later delivery services must recheck purpose, consent, generation and outbox authority.

Synthetic tests include ten simultaneous first contacts, competing revision-zero callbacks with one winner, stale replay, foreign and same-brand other-actor failures with prior-write rollback, wrong listing/order, expiry, independent preferences, stopped bots and blocked/banned/never-started destinations. The native executable repeats actual database membership creation, preferences, flow revision, destination and stale rejection. Full localized output, verified ingress, public contacts/channel exemptions and support runtime remain later tasks. No schema changes, real credentials/source rows or live services.
