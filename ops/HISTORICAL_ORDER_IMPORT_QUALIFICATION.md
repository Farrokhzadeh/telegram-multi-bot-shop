# Historical wallet order import implementation

Source review is pinned to AccAbad-Shop `66371a23a1c8149dc5bdf89a0355aa689d454dba`: `apps/store/models.py`, `apps/common/services/checkout.py`, `apps/common/services/discounts.py` and `apps/common/services/pricing.py`. The reviewed `Order` owns one product and quantity; `_create_order` generates the original public order alias. This does not prove deployed schema. The source reader rejects a copy containing `public.order_items` and requires the committed schema and record fingerprints.

`ImportWorkflow.ImportOrderAsync` now composes source reading with a repeat-safe historical wallet order writer. The supported projection requires version-1 USD credential snapshots with wallet provenance, matching product/quantity/total, positive price and no discount. Other snapshots fail closed. Historical brand naming must come from the protected approved projection: it is committed into a separate target-snapshot fingerprint, never inferred from the current target brand. Membership must match the manifest source user and trusted brand/bot.

Three mappings commit with the target order: source row, target snapshot and genuine public alias. Historical products may be absent under the existing restricted import-role guard. The complete source checkout snapshot is retained as payment terms, together with original title, quantity, USD unit value and timestamp. USD maps to the target USDT pricing denomination under this explicit legacy projection; no wallet amount is converted or posted. Original source JSON remains evidence, not new live pricing authority. Non-applicable target TOMAN policy fields use the explicit `legacy-wallet-v1` projection defaults (automatic TOMAN pricing disabled, 5000 rounding step); these are not claimed as recovered source values.

Imported rows remain `requires_admin/credential_recovery`, with no fulfillment, stock, payment, purchase debit, supplier request, manifest release or customer send. This is a review quarantine, not proof that a source order is undelivered. Historical delivery evidence still needs its own adapter and import before obligation acceptance. The writer rejects replay if the target has drifted. Import audit and alias writes share the transaction.

`CompareOrdersAsync` compares the manifest-bound source/projection to stored target snapshots, counts missing source expectations and target mismatches, and includes missing/mismatched mappings. It returns redacted counts, a limited scope and `ReleaseReady=false`. It does not establish record equivalence for payment, coupon or delivery history.

Synthetic tests are written for replay, genuine alias retention, unchanged opening balance, no new debit/stock/fulfillment, modified projection rejection, changed target detection, unmatched expected source orders and unsupported/non-USD/discounted snapshots. Execution is delegated to GitHub Actions; no local .NET execution is claimed.

T063, T064 and T066 remain unchecked. Remaining independent implementation includes catalog, payment attempts/manual deposits, coupon ownership/provenance/current-use/ciphertext preservation, historical delivery/partial-delivery evidence and full source-bound reconciliation. Protected actual source-copy reconciliation and intended-environment qualification remain external gates. No environment mutation or release is authorized by this implementation.
