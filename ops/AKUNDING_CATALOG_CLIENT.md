# Akunding read-only product inspection

This client implements one documented GET for an explicitly supplied numeric product ID. It returns account-specific single-unit price, stock and descriptive unit metadata in the supplier's USDT denomination. It does not enumerate/import/publish products, implement ISupplierAdapter, attest eligibility, bind a payable quote or expose any purchase operation. The administrator chooses individual credential/key/code products and exact mappings; unrelated catalog entries do not block a supplier integration.

Composition supplies an independently trusted HttpClient with same-account authorization from the existing protected credential snapshot, cookies disabled and automatic redirects disabled. Do not bind a default or untrusted transport to a normal host. No credential loader, account configuration, runtime endpoint or host activation is added in this checkpoint. Authentication headers belong to that protected transport and are never returned by the client. Synthetic handler injection qualifies parsing only, not deployed credential custody or provider capability.

The product ID must match the requested identity. Required fields, exact decimal prices, consistent stock/availability, duplicate properties, HTTP failures, malformed payloads, bounded size and a 25-second linked deadline are checked. Caller cancellation propagates; other failures are sanitized and are never automatically retried. Stock zero remains descriptive sold-out metadata. Unit labels alone are not eligibility proof. Bulk-tier pricing is not used: this is a single-unit inspection, not a quantity purchase quotation.

Source: https://akunding.shop/api/docs (product detail and product-object sections). Tests contain generated public-shaped examples only, without supplier credentials, live-account catalog rows or account-specific observations. Full exact-commit CI supplies build, analyzer, formatting, test and native regression checks. T057/T091 procurement gates and FR-074 remain open. Before runtime composition, qualify the protected transport, current-account binding and exact product eligibility separately. No new dependency, table, migration or production operation is introduced.

## Protected administrator source preview

AkundingSourceInspection composes the client with SupplierCredentialSnapshot, matching the commerce deployment/service and exact configured account. It owns a nonredirecting, cookieless transport by default. An optional injected transport is a trusted qualification/composition dependency, never a caller-selected remote target. Each request resolves its bearer credential through the protected snapshot; the request header is cleared after transport. No token is returned in preview metadata or diagnostic text. Credential snapshot ownership stays with the caller.

InspectAsync requires a current independent administrator, an existing exact product/source mapping and its expected revision. Only Akunding mappings with canonical positive numeric external IDs and no variant qualify. It supports disabled candidate mappings for preview and performs no enable/select/publication mutation. It rechecks authentication and the product/source revision after the read, without retaining database locks over transport. Changed mappings, revocation and missing/disposed credentials reject the preview. The result preserves provider USDT metadata; it is not a CatalogStore ready-item observation or a purchase quote.

Generated credential files and disposable fixtures exercise authorization, account/deployment/service separation, changed-product and revoked-admin races, exact mapping and zero publication/procurement effects. No live-account results, actual keys or supplier product rows are saved. Normal hosts and the frozen administrator HTTP surface remain unchanged; the existing internal source administration workflow can call this preview explicitly. Administrator-selected credential/key/code mappings remain the intended scope. Do not auto-import a catalog or infer readiness from a unit label. Purchasing, mapping enablement and runtime deployment retain their separate gates.
