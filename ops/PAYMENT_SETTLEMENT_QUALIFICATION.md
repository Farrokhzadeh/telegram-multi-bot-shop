## Bank receipts and status reads

ManualDepositService records the protected receipt and the database observation clock without holding stock. Timely submission protects the original order as under_review. Denial is explicitly unverified and retains review/claims; a later separately audited approval can confirm the original receipt. Current independent administrator authentication, original receipt, expected order revision and content-checked command UUID are required. Approval records the exact frozen toman amount and paid history, then reuses the accepted-order dispatcher in the same transaction. Immediate local bank shortages remain paid/unfulfilled with all held uses and no expiry or automatic USD credit. Late/terminal bank receipts stay staff-reviewed without credit or revival.

An explicit paid-unfulfilled reconciliation command appends only its administrator audit. It does not record/infer an outside-shop payout or refund, cancel an order or release a claim. Separately authorized staff order-state actions remain their own later implementation.

BankDestinationService encrypts the receiving number/holder under the selected brand key and uses one protected shared HMAC fingerprint key for duplicate detection. Revision-checked, audited successful saves replace the one destination for new orders; stale/conflicting writes reject. Cross-brand active-card reuse rejects at the canonical unique index. Existing payment ciphertext and original deadlines remain immutable. Runtime provisioning/rotation of the protected shared fingerprint key remains an activation gate.

PaymentReadStore exposes original quote/payment/fulfillment/review state, actual internal USD posting and coupon-state/expired-return information. Customer reads resolve the original membership; administrator reads require an active independent session and explicit brand scope. The two opt-in GET routes are `/v1/admin/payments/{id}?brandId=...` and `/v1/admin/manual-deposits/{id}?brandId=...`. Source-generated responses contain no receipt/archive reference, provider identity, card/holder, ciphertext, signature or credential. Loopback HTTP tests qualify unauthenticated denial, same-brand reads, foreign-brand not-found and revoked-session denial. Normal Api/BotHost/JobHost startup remains fail closed; these routes are not mounted by normal hosts.
