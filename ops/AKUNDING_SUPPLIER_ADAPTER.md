# Akunding wire adapter and local price guard

The owner approved option A on 2026-11-04: use a fresh exact-product price check within the immutable inclusive 10% allowance, accepting that an uncapped provider can execute at a different price afterward. SupplierRules no longer requires EnforcesMaximum=true. The property remains factual; Akunding sets false and sends no invented maximum-price or quote field. Customer terms and accepted cost baseline never change. A higher actual response charge retains verified acquired units for administrator cost review without automatic release, repeat purchase or credit/refund.

AkundingSupplierAdapter composes with the existing worker, request/attempt store and CatalogStore. It requires protected same-deployment/service/account credentials, an explicit set of reviewed product approvals and a separately qualified unit-identity resolver. Normal hosts do not instantiate it; no real credentials, catalog rows, requests or deployment are included in this checkpoint.

## Product review

Catalog detail exposes Description, Features and an EligibilityFingerprint when the documented string fields exist. The versioned digest binds the exact numeric ID, name, unit label, description and features; price and stock are excluded. A trusted operator reviews the selected credentials-only product and supplies its exact fingerprint/content kind to AkundingProductApproval. A fingerprint is a change detector, not independent proof of eligibility. Missing fields, unapproved products and changed metadata fail readiness. The adapter does not automatically approve any catalog entry, collect customer inputs or infer readiness from its unit label. The configured approval list is composition data; no additional table or generic payload is introduced.

Fresh direct catalog observations support mapping enablement and pre-checkout checks through InspectCatalogAsync, retaining native USDT. Full-local coverage keeps its existing bypass. InspectAsync obtains the exact selected item, stock, identity and reviewed metadata; it issues a bounded, single-use in-memory permit tied to the whole immutable binding and fresh quote. Submit consumes the permit after the worker's durable attempt commit, rechecks its 30-second freshness/local threshold and sends one POST /api/v1/orders with only numeric product_id and quantity and the original X-Idempotency-Key. There is no automatic HTTP retry. One-unit your_price is used conservatively; lower bulk-tier pricing is not invented or used as an unbound discount.

## Original purchase recovery

Lookup uses only GET /api/v1/orders/{original_id}. It never replays a POST, searches recent orders for a guess or creates a replacement key. ProvenIntentLookup=false: a lost response without an original remote order ID remains for manual reconciliation, including after lease expiry. A stale or missing local permit proves no POST was made by this invocation and returns a local confirmed-no-effect receipt; it does not erase any earlier attempt.

Bounded JSON reads enforce exact product, order (for lookup), quantity, API status, wallet method, decimal unit/subtotal/discount/payable consistency and complete delivered item count. HTTP errors, malformed/ambiguous bodies and transport failures preserve unknown outcomes, with bounded original evidence when captured. No non-2xx response implies a safe repurchase. Paid is processing; draft remains unknown. Failed is the documented no-items, wallet-recredited terminal state, subject to the existing archived no-effect and explicit admin-retry checks. Original evidence is copied to the existing protected archive boundary before persisted acquisition; temporary byte buffers and disposable receipt/item buffers are cleared.

## Unit-identity requirement

The public Akunding contract returns strings, without stable per-unit IDs. The adapter does not manufacture remote identities from array positions, order numbers or credential hashes. Its trusted identity resolver must be independently qualified for the chosen products and returns proven unit references with exact original credential bytes. Returned content multiplicities, dispositions, kinds and reference uniqueness are checked. Content hashes are used only for transient byte-set comparison, never as supplier identities. The core still enforces global item deduplication and encrypted customer/bonus separation.

An unresolved resolver can return no items; the archived delivered response remains an incomplete acquisition requiring review, with no fabricated fulfillment or customer release. This is an explicit remaining provider-qualification dependency, not a passing real identity claim. Runtime account/eligibility/identity/archive qualification remains necessary before automatic customer delivery. Other four current suppliers and nine saved future APIs remain unqualified; this checkpoint does not finish T057/T091/T092/T093/T094.
