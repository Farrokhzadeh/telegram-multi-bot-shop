## Execution & Async Workflow
- **Git & CI:** Work directly on `main`; never create branches. Batch related validated changes by task. Build/test CI is authorized when needed; add `[skip ci]` otherwise. Deployment and cutover require separate authorization.
- **Single-Agent Parallelism (No Subagents):** Do not spawn subagents unless explicitly requested. Instead, multitask asynchronously:
	- Run long commands in bounded, resumable background jobs (private logs, exit codes, progress) with strict CPU, memory, connection, and concurrency caps.
	- Never sit idle while jobs run—immediately handle independent reads, plans, or edits on non-overlapping files. Never mutate shared files or databases concurrently.
	- Batch independent file reads, searches, and edits into single turns.
	- Poll background jobs cheaply (exit code + `tail -n 20`) only between completed steps—never dump full logs into context.
- **Reuse & Pre-flight:** Map existing code/evidence to remaining gates before coding. Reuse functions, deps, builds, pinned images, and isolated restores only when inputs, scope, and freshness match. Before heavy work, verify access, tools, disk/RAM, backup readability, keys, isolated DB connectivity, and hazards. Validate synthetic cases (target image, UID, mounts, auth, limits, empty data/dirs) before protected runs.
- **Staging & PM Split:** Default to one isolated staging brand; add brands only for shared-state/tenant-isolation or required final gates (reuse matching prior evidence). Never use production bots for routine checks. Derive technical facts yourself; ask the owner only concrete product decisions unresolvable from approved requirements.
- **Testing & Checkpoints:** Run baseline checks, focused checks while editing, and full checks at phase/final gates. Rebuild on code/dep changes; rerun broader passing checks only on changed inputs, failures, or open risks. Report unavailable checks honestly. Bind checkpoints to input IDs, scope, and tool/runtime versions and revalidate as needed—caller counts, unsigned receipts, sampling, or checkpoint presence alone never prove full runs. Investigate discrepancies; keep failed attempts and corrections.
- **Runtime & Ledger:** Preserve empty directories during staging. Probe managed .NET JIT backing-file limits separately from memory limits; reuse qualified settings only where applicable. Maintain a terse ledger: commit, validated hashes, passed gates, private evidence refs, blockers, exact next action (prefer generated redacted summaries over manual counts).

## Data & Operational Safety
- **Copied-Data Isolation:** Use `accabad-server` only for authorized isolated copied-data work. Check ownership, labels, image, mounts, auth, and network isolation before restarting copies. Never touch live DBs, bots, or production media. Same-server staging shares host failure risk—never run host-destructive tests there.
- **DB Reconciliation:** Use explicit read-only transactions and restricted roles. Verify source identity/commitments (start and end) plus target/archive/quarantine coverage. Index creation is a write—allowed only on authorized isolated copies, with schema effects reconciled before qualification.
- **Privacy & Secrets:** Keep customer data/IDs, monetary values, keys, private receipts, and protected evidence on the owner server. Publish only authorized redacted evidence; keep secrets out of Git. Verify file ownership, permissions, symlink/hard-link safety, input hashes, and staging boundaries.
- **Financial & Quarantine Rules:** Preserve every ambiguous original under quarantine policy. Never infer settlement, ownership, delivery, financial links, or release readiness from missing facts. Preserve denominations, historical money, and original refs; never guess FX, activate imported stock/discounts, or waive liabilities. Retain keys while any archive, backup, or rollback dependency remains.
- **Hard Gates & Fail-Closed:** Separate authorization/evidence is required for staging/cutover, live supplier/payment/Telegram/FX/AI calls, production writes, deployment, and key retirement. Prevent old/new simultaneous saleable stock; preserve single-brand writer/callback ownership, rollback, and independent stop controls. Leave unfinished tasks unchecked and hosts fail-closed until gates pass. Keep read-only reviewer checklists/hashes intact; partial, synthetic, or governance evidence qualifies only its stated scope.

For shared commerce/suppliers, consult [schema contract](specs/001-multibrand-redesign/schema-contract.md), [supplier matrix](specs/001-multibrand-redesign/contracts/supplier-provider-matrix.md), and [API inventory](ops/API_INVENTORY.md) (docs never authorize live calls).

## Code, Environment & Communication
- **Code Style:** Write the simplest correct solution. Keep code compact (single-line for simple expressions where valid and allowed by formatting). Use one literal tab per indent level where tooling permits; never mix indentation in a block.
- **Zero Bloat:** No code comments (keep required licenses/tooling directives only). Use short meaningful names, minimal diffs, and existing utilities; avoid duplicate logic, speculative abstractions, and unrelated reformatting.
- **Environment:** Default to local/home-network services, localhost binding, and configurable hosts/ports. Inspect live tools instead of relying on old environment assumptions.
- **Output:** Keep replies short, accurate, and plain. Explain unfamiliar terms simply. Report milestones and real blockers; omit raw diffs and internal thinking.
