## Encryption representations and reader boundary

Authoritative source: [crypto.py](https://github.com/Farrokhzadeh/AccAbad-Shop/blob/7fcc4a7a35337405dd69195fc6c92474748c4513/apps/common/crypto.py#L1), blob `37629fe383d75f17682825ff75b3154637ebaa1e`; [custom fields](https://github.com/Farrokhzadeh/AccAbad-Shop/blob/7fcc4a7a35337405dd69195fc6c92474748c4513/apps/common/fields.py#L1).

- Secret text uses `enc:v1:` and historical `enc:`; encrypted JSON text uses `encjson:v1:`; inventory/supplier text fields use `enctext:v1:`. Empty/plaintext source forms require explicit field mapping/recovery permission.
- Source raw key selection is FIELD_ENCRYPTION_KEY or Django SECRET_KEY, with FIELD_ENCRYPTION_KEY_PREVIOUS as a rotation fallback. Strip an optional `fernet:` marker; accept a valid 44-character URL-safe Base64 key decoding to 32 bytes; otherwise SHA-256 the UTF-8 raw value. These are names/algorithms only; no real values were read.
- Fernet validates version, HMAC-SHA256 and AES-128-CBC/PKCS7; source decrypt has no TTL argument. The migration-only C# reader checks authenticated structure and strict UTF-8, tries provided keyring values and fails closed on unsupported encrypted representations. It cannot encrypt or become a fallback for new target ciphertext.
- Public deterministic vectors in tests/fixtures/legacy-fernet-synthetic.json were generated and independently decrypted with Python cryptography 50.0.2. They cover every known prefix, direct/prefixed/raw-derived keys, Unicode and previous-key fallback. They prove synthetic interoperability only; E3 still requires authorized real-format samples and protected restore proof.
- Existing source field serialization writes ciphertext for backups. Preserve original ciphertext, source provenance and dependency-based old-key retirement; never decrypt/export a source database during this batch.
