# Offline qualification

1. Run `dotnet run --project src/Platform.SchemaRunner -- --initialize-staging-sqlite /absolute/staging/shop.db` on a disposable empty file in an existing private directory. Seed only synthetic brand, administrator, catalog and stock fixtures. The isolated synthetic PostgreSQL staging snapshot-copy path is separate and must verify source/target schema, row identities and coverage; neither path may touch production or protected legacy records.
2. Run the existing .NET suites through [backend CI](../../.github/workflows/backend-ci.yml) for the exact candidate commit, including PostgreSQL regressions. Compare canonical constraints and affected SQL columns; verify catalog/admin tenant permissions, UUID pagination, coupon/prepaid and wallet/crypto/bank flows, supplier/review outcomes, and synthetic provider boundaries. Run concurrent checkout and replay verified callbacks; assert one settlement/entitlement, exact monetary amounts and stock, and no duplicate allocation or redemption.
3. Inject rollback/cancellation, busy-writer and crash/restart cases, including uncheckpointed WAL, evidence archive interruption, uncertain Telegram/supplier outcomes and stale job leases. Restart worker, bot and API against the same directory; verify accepted balances, postings, jobs, manifest and delivery markers persist. Prove compatible SQLite-executable rollback or fail closed without a PostgreSQL writer.
4. Only after full candidate qualification and separate staging authorization, open GitHub Actions → **Offline backend qualification** → **Run workflow** on `main`; set `deploy_staging=true` and explicitly select `staging_backend=sqlite` (default `none` must skip deployment). Manual dispatch cannot infer the SQLite mode from a push commit message. Confirm the deployment targets only the isolated synthetic staging brand, with no live providers or production access. Check image digest/revision, service identity, authenticated health, persistent mount and post-restart SQLite state; prove same-database SQLite rollback or fail-closed recovery. Do not infer T003–T008 completion from a healthy service alone.
